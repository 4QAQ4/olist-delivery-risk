Olist 订单延迟预测：最终建模实验报告
本报告根据项目中已完成的基线、逻辑回归与随机森林 Notebook 及记录整理。模型最终版本为未加权随机森林。没有提供的 EDA 图表数值和运行环境版本未在此编造。

1. 任务定义
目标：在订单获批时，根据此前已经可知的订单信息，预测该订单是否会晚于预计送达日完成配送。

预测时点：order_approved_at。

目标变量：is_delayed。使用日历日期而非完整时间戳比较：
is_delayed = (
    order_delivered_customer_date.dt.normalize()
    > order_estimated_delivery_date.dt.normalize()
).astype(int)
上述代码仅示意两列均有效且送达状态已核实的样本的标签规则；实际缺失送达时间不能自动标为 0。实际送达时间用于标签和时间可用性检查，不放入模型输入。

数据来源：Kaggle Olist Brazilian E-Commerce Public Dataset；第一版只使用订单表、订单商品表、客户表。订单商品明细按 order_id 聚合后得到一行一订单的数据。
2. 时间划分与标签可用性
按 order_approved_at 确定约 70% / 15% / 15% 的时间边界；随后：
- 训练集：获批时间在验证期开始前，且订单在验证期开始前已经送达。
- 验证集：获批时间在验证期内，且订单在测试期开始前已经送达。
- 测试集：获批时间在测试期内，沿用构造完成的有效标签数据。
数据集	样本数	延迟率
训练集	64,381	6.82%
验证集	12,544	4.30%
测试集	14,456	4.28%


这些样本数量是应用时间与标签可用性筛选后的结果，不应当直接等同于原始 Olist 订单总数。训练集延迟率高于验证、测试集，需注意时间分布变化和筛选引起的选择偏差。
3. 评价指标
- AP（Average Precision）：主要比较风险排序的指标；常数评分下的 AP 等于所在数据集正类比例。
- Precision：判为延迟的订单中，实际延迟的比例。
- Recall：实际延迟的订单中，被识别出的比例。
- F1：Precision 与 Recall 的调和平均。
- PR 曲线：用于呈现不同阈值下的 Precision–Recall 权衡。
考虑到延迟订单属于少数类，不以 Accuracy 作为主要结论。分类阈值只从验证集选择，再应用到测试集。
4. DummyClassifier 基线
使用 DummyClassifier(strategy="prior")：只学习训练集正负类比例，不依赖输入特征，类别预测均为未延迟。

5. 逻辑回归模型
5.1 输入与预处理
共使用九项特征：
- 数值（7）：purchase_month、purchase_weekday、purchase_hour、approval_hour、item_count、product_amount、freight_amount。
- 类别（2）：customer_state、customer_city。
数值特征用 StandardScaler，类别特征用 OneHotEncoder(handle_unknown="ignore")，仅对训练集拟合预处理器。编码后特征矩阵为 3,710 列。

逻辑回归使用 LogisticRegression(max_iter=1000, random_state=42)，实际训练迭代次数为 122。
5.2 验证集指标
评价方式	Precision	Recall	F1	AP
默认阈值 0.50	0	0	0	0.068645
六个候选阈值中选择的 0.08	0.0650	0.4100	0.1122	0.068645

5.3 错误案例分析
- 对验证集提取过预测概率较高的 5 笔误报及预测概率较低的 5 笔漏报订单。
- 另外使用分析阈值 0.15 对全部 FP / FN / TP / TN 分组，比较商品金额、运费、商品数量和预测概率。
- 在这项统计中，FP 平均商品金额约 296.88、平均运费约 46.49；TN 对应约 137.49 和 21.58。
- 这些属于模型分组特征差异，不能直接解释为高金额、高运费导致延迟或误报。
提醒：错误案例分析用的阈值 0.15 与逻辑回归用于比较 F1 的阈值 0.08 不同，报告和讲解时需分别说明。

6. 随机森林实验
6.1 初始模型
最初使用逻辑回归相同的九项特征，RandomForestClassifier(n_estimators=120, max_depth=16, min_samples_leaf=10, max_features="sqrt", random_state=42)，验证集 AP 约 0.069742。
6.2 特征工程与消融
新增尝试：
- promised_days：预计送达日历日期减去获批日历日期，单位为天。
- seller_hist_delay_rate：卖家截至当前订单获批前，已经送达订单的历史延迟比例。
- seller_hist_order_count：卖家截至当前订单获批前，已经送达订单的数量。
卖家历史信息通过原始订单商品表中的 seller_id 构造，不需要新增卖家维表；但卖家历史特征在最后并没有入模。

只有最终随机森林有明确记录的独立测试集 Precision、Recall、F1 和 AP；本报告不假定基线和逻辑回归已经完成测试集评估。
8. 已知局限与合规解释
1. 类别不平衡：验证、测试的延迟率仅约 4.3%，整体 Precision 偏低。
2. 时间泛化：测试 AP 0.084813 低于验证 AP 0.113722；不同时期的订单或配送条件可能变化，但目前未做充分归因。
3. 标签筛选偏差：训练和验证集排除截止点前尚未送达订单，可能造成已送达样本的选择偏差。
4. 特征边界：第一版仅三张原始数据表；没有真实物流轨迹、卖家地理维表等特征。
5. 预计日期可用性假设：promised_days 依赖订单获批时已经可知的预计送达日，需明确该假设。
6. 风险与收益：离线模型没有做实际业务部署，也没有验证预警可以减少迟到。
7. 测试集使用说明：此前测试指标已经被查看；之后没有将加权实验模型设为最终版本。应如实记录评估历史，不应表述为在全部决策过程里始终完全不可见的盲测集。
9. 最终结论
本项目完成了 Olist 订单级建模数据整理、时间划分、简单基线、逻辑回归和随机森林评估，并进行特征消融、阈值分析、错误样本研究和特征重要性解释。

最终模型：八项特征、class_weight=None 的随机森林。

主要结果：验证集 AP 0.113722、F1 0.200129；测试集 AP 0.084813、F1 0.159129。模型有一定风险排序能力，但仍有明显误报和泛化局限。
